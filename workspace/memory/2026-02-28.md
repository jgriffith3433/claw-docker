## Unity MCP Reliability Fix (Evening)
- Root cause: MCP WebSocket server doesn't reliably restart after domain reload
- Settings file correct (`AllowRemoteConnections: true`, `AutoStartServer: true`) — server just fails to rebind
- Persistent bridge (`unity-bridge.mjs`) attempt: SSE transport + watchdog — initial connect works but reconnection unreliable
- **Fix**: `Assets/Scripts/Tools/Editor/McpServerMonitor.cs` — [InitializeOnLoad] script, checks every 5s via reflection + TCP, auto-restarts
- Removed `unity-bridge` from mcporter; back to stdio-only (`mcporter call unity`)
- Created `scripts/unity-call.sh` — retry wrapper (3x, 5s delay)
- Status: McpServerMonitor needs one manual MCP restart to compile (chicken-and-egg), then it's permanent

## Rewind System
- **GameClock** (SickOfIt.Core) — master time, forward/backward/pause/seek
- **StateRecorder** — snapshots every 0.1s: player pos/vel/health, enemy pos/health/active, camera pos/zoom. Ring buffer, 10s history.
- **RewindController** — MobileControllerFramework Button input, VHS overlay, rewind sounds, mutes music during rewind
- During rewind: presentation events (SFX, shake, flash) fire FORWARD, state events (spawns) handled by StateRecorder snapshots
- ExperienceRunner walks event index backwards during rewind, only fires IsRewindSafeEvent types
